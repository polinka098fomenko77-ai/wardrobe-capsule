# Сценарій демонстрації: від порожньої бази до готової роботи

Кожен етап: що робимо, команда, що має вийти, що сказати комісії.
Усі команди виконуються з кореня проєкту `~/wardrobe-capsule`, якщо не вказано інше.

## Перед початком
- Відкритий Docker Desktop (статус "Engine running").
- Встановлені Node.js та npm.
- Чотири вікна/вкладки термінала: **A** (база і скрипти), **B** (backend), **C** (frontend), **D** (перевірки).

---

## Етап 1. Порожня база даних
**Що показуємо:** проєкт стартує з нуля, база не містить жодних даних.

Вікно A:
```bash
./scripts/reset-demo.sh
```
**Очікуваний результат:** список із 8 таблиць (7 наших + службова `_prisma_migrations`) і `0` користувачів.

**Що сказати:** «Схема бази описана в `backend/prisma/schema.prisma`. Prisma створила з неї SQL-міграцію, яка лежить у репозиторії, тому будь-хто відтворить базу однією командою. 7 таблиць: User, UserPhoto, Store, Item, ItemSize, TryOn, WardrobeItem».

Додатково можна показати структуру в браузері: `cd backend && npx prisma studio` (http://localhost:5555).

## Етап 2. Запуск серверної частини
Вікно B:
```bash
cd backend
npm install
npm run dev
```
Вікно D:
```bash
curl http://localhost:4000/health
```
**Очікується:** `{"status":"ok","db":"up"}`.

**Що сказати:** «Backend на Node.js, Express і TypeScript. Маршрут `/health` перевіряє, що сервер бачить базу».

## Етап 3. Запуск клієнтської частини
Вікно C:
```bash
cd frontend
npm install
npm run dev
```
Відкрити в браузері адресу з терміналу (зазвичай http://localhost:5173).

**Що сказати:** «Frontend на React і TypeScript, зібраний Vite. Є українська та англійська мови, світла і темна теми».

## Етап 4. Реєстрація
В браузері: заповнити форму (ім'я, прізвище, нікнейм, email, пароль, мірки в см) і натиснути «Продовжити».

Перевірка в базі (вікно D):
```bash
docker exec wardrobe-db psql -U wardrobe -d wardrobe -c 'SELECT id, email, nickname, "passwordHash" FROM "User";'
```
**Очікується:** рядок користувача; пароль збережений у вигляді хеша (`$2a$10$...`), не відкритим текстом.

**Що сказати:** «Пароль хешується алгоритмом bcrypt із сіллю. Дані перевіряються бібліотекою zod: допустимі межі зросту, формат email, довжина пароля. Після реєстрації сервер видає JWT-токен».

## Етап 5. Вхід і захищені маршрути
1. У меню профілю натиснути «Вийти», потім увійти за email і паролем.
2. Показати захист (вікно D):
```bash
curl -i http://localhost:4000/me
```
**Очікується:** `401` без токена.

**Що сказати:** «Токен JWT підписаний секретом сервера й діє 7 днів. Маршрути профілю перевіряють його через middleware, тому без входу дані недоступні».

## Етап 6. Профіль
Показати: зміну нікнейма, імені, email, мірок, пароля; перемикання теми й мови.

**Що сказати:** «Користувач може змінити всі дані, введені під час реєстрації. Для зміни пароля потрібно ввести поточний».

## Етап 7. Фото
1. У профілі завантажити аватарку.
2. У пункті меню «Фото для примірки» завантажити фото.
3. Показати спробу завантажити не зображення (відхиляється).
4. У базі (вікно D):
```bash
docker exec wardrobe-db psql -U wardrobe -d wardrobe -c 'SELECT id, "userId", "storagePath", "expiresAt" FROM "UserPhoto";'
```
**Що сказати:** «Тип файлу перевіряється за вмістом, а не за розширенням. Фото для примірки приватне: його віддає сервер лише власнику. Воно автоматично видаляється через 7 діб (поле `expiresAt`)».

---

## Етап 8. Камера з підказками
**Підготовка (один раз на новому комп'ютері):** `./scripts/setup-camera.sh` (копіює wasm і завантажує модель обличчя).
1. «Фото для примірки» → «Зробити фото камерою» (адреса `/camera`). Дозволити доступ до камери.
2. Показати підказки: повернути голову вбік (з'являється «Трохи поверніть голову…»), відійти/наблизитись, закрити об'єктив рукою (попередження про темряву).
3. Вимкнути світло або затулити частину світла: індикатор «Низьке, виправимо». Натиснути «Зробити знімок»: кадр підсвічується автоматично.
4. «Зберегти фото»: воно з'являється у «Моїх фото».
**Що сказати:** «Розпізнавання обличчя працює прямо в браузері (MediaPipe Face Landmarker, 478 точок), відео нікуди не надсилається. Поворот голови рахуємо за положенням носа відносно країв обличчя. Темний кадр вирівнюємо гамма-корекцією. На сервер йде лише готовий знімок через той самий захищений `POST /photos`».

## Наступні етапи (будуть додані, коли реалізуємо)
- **Етап 9.** Каталог: фільтри за ціною, розміром, кольором, наявністю; щоденне оновлення.
- **Етап 10.** Примірка верхнього одягу на фото за допомогою ШІ.

## Якщо щось не працює
| Симптом | Що робити |
|---|---|
| `Cannot connect to the Docker daemon` | Відкрити Docker Desktop і дочекатися запуску |
| `port is already allocated` | Порт 5434 зайнятий: змінити його в `docker-compose.yml` і `backend/.env` |
| Сайт пише "Сервер недоступний" | Запустити backend (вікно B) |
| Після скидання бази сайт просить увійти | Це нормально: старий токен вказує на видаленого користувача. Вийти й зареєструватися знову |
